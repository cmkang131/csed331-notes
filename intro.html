왜 알고리즘인가

문제 정식화

  • algorithm : 문제를 푸는 절차, 모든 컴퓨팅 응용의 바탕
  • 현실 문제 = 도메인 조건 + 군더더기 정보가 섞여 있음
    • 예 : 교실 시간표 배정, 전국 단위 배송 같은 큰 문제
  • problem formulation(문제 정식화) : 추상화·단순화로 핵심 구조만 남기는 것 → 이 과목에서 가장 먼저 기르는 능력
  • 과목 목표
    • 문제를 체계적으로 정식화
    • 정확하고(correct) 효율적인(efficient) 알고리즘 설계
    • 시간·공간 복잡도 분석
    • 기본 설계 기법 → 고급 주제 순서로 진행

수업 방식 (강의 + PBL)

강의와 팀 프로젝트

  • 전통 강의(개념, 설계 전략) + 팀 기반 PBL (Project-Based Learning)
    흐름 : 이해 → 실험 → 구현 → 발표
  • PBL 특징 : driving question, 반복(프로토타입 → 테스트 → 수정), 현실 제약, 협업, 공개 결과물(demo, report)
  • 산업에서는 이미 표준, AI 시대에 학계 표준이 되는 중
    • 정보를 찾아오는 것 ≠ 아는 것 → 직접 만들어 보는 과정을 넣은 이유

PBL 진행과 평가

  • 단계 : 할 일
    • Define : 범위, 요구사항, 평가 지표
      Design : 후보 방법, 근거, 위험 분석
      Build : 구현, 도구, 버전 관리
      Evaluate : 실험, 벤치마크, 피드백
      Communicate : 데모, 보고서, 발표, 회고
  • 평가 : 과정(마일스톤, 설계 리뷰) + 결과물(정확성, 성능, 사용성) + 근거(로그, 실험 비교) + 팀워크(기여 기록, 동료 평가)
  • 결과물은 직접 테스트하고 개발 기록도 확인함
  • 한두 명만 일하는 팀은 안 됨 → 역할 순환, 짧은 보고로 막음
  • 자주 하는 실수
    • 먼저 만들고 나중에 생각 → 설계 문서 + 리뷰 단계 필수
    • 범위 과다 → MVP 먼저
업계 예시
  • Google : 멘토링·결과물 중심 프로젝트, CS First 커리큘럼
  • Amazon Technical Academy : 강사 주도 + project-based
  • Apple CBL (Challenge-Based Learning) : Engage → Investigate → Act, 프로젝트보다 도전 과제에 초점
